# AGENTS.md

Go backend + React/TS frontend for a searchable S3 file index.

See DESIGN.md for architecture rationale (its "Plan" section is historical
— all items done, not a to-do list), NOTES.md for later decisions not yet
folded into DESIGN.md, README.md for human quickstart. Run `just` for the
full, self-documented command list.

## Codegen — never hand-edit

- `internal/db/*.sql.go`, `internal/db/db.go`, `internal/db/models.go` —
  sqlc, from `internal/db/queries/*.sql`
- `internal/pb/**` and generated web TS protobuf clients — buf, from
  `proto/`
- `mocks_test.go` files colocated in each `internal/service/*` package —
  mockery, config in `.mockery.yaml`

Run `just generate` after touching migrations, queries, `.proto` files, or
interfaces listed in `.mockery.yaml`, and commit the output.

## Test conventions

- Table-driven tests, standard library `testing` only — no external
  assertion libraries.
- Mocks generated by mockery, colocated with the interface's consumer.
- Integration tests: `//go:build integration`, excluded from
  `go test ./...`; only add when real DB/S3 interaction is required.

## Invariants (see DESIGN.md for rationale)

- **S3 is the single source of truth.** Nothing is indexed unless it lives
  in S3; the DB is a derived search index, not a store.
- **Reference-based indexing.** Index requests carry only `(source, s3 key)`
  — never file bytes. The indexer GETs the object itself and computes all
  metadata, uniformly across API, uploader CLI, and crawler paths.
- **Idempotent indexing.** Re-indexing the same key must be safe (upsert
  semantics); the crawler may re-emit references for unchanged files.
- **Crawler skips derived objects.** Preview images are written back under
  the `INDEX_PREFIX` key prefix; the crawler ignores that prefix so derived
  objects never become `files` rows.
